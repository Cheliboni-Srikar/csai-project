## Workflow

1. Study a concept and record a supporting source.
2. Draft definitions, a worked example, an activity, and an explained answer.
3. Make a focused change with a meaningful commit message.
4. Have another member check the actual file/version and record findings.
5. Correct the source content and update every affected visual, answer, slide, or script.
6. Trial the activity, collect feedback, and repeat the checks after substantive changes.

If one member uploads another person’s work, record both author and uploader with evidence. Do not infer effort from commit counts or manufacture extra commits.

## Planned use of checked content

- Study guide/test bank: six chapters, diagrams, examples, short quizzes, and explained answers.
- Slides: clear visuals for facts/rules, forward/backward inference, and search paths.
- Video: short narrated demonstrations using the same vocabulary and examples.
- Mini lecture: “How can a computer reason using IF–THEN rules?” Use the Chapter 3 card activity and a missing-fact prediction.

## Risks and responses

- Abstract concepts: use one concrete adviser example, define terms, and check learners can explain each step.
- Incorrect or incomplete rules: compare worked results with independent calculations and record peer review.
- Missing images: keep assets in the repository and validate relative links in an extracted copy.
- Uneven workload: confirm a lead and reviewer for small tasks and review progress together.
- Unclear course depth: ask the teacher about formal logic/search expectations before expanding those sections.
- Stale resource versions: update the Markdown source first and track changes needed in slides and videos.
